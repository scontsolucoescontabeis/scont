O Boas Vindas vive em Projeto Boas Vindas/. Mesma stack do resto do portal — HTML/JS puro, sem framework/bundler, cliente Supabase próprio por arquivo (createClient(SUPABASE_URL, SUPABASE_KEY) com a chave anon de supabase-config.js). Duas superfícies distintas: admin/admin.html + admin-script.js + cnae.js (painel interno, cria e gerencia apresentações — protegido por portal-auth-guard.js, exige auth.isAdmin) e index.html (página pública que o cliente recebe por e-mail/WhatsApp — sem nenhum auth guard, acessível por qualquer um com o link). O catálogo de CNAEs é reaproveitado de outra ferramenta do portal (Projeto Gerenciador Formularios/cnaes.js, carregado via <script> relativo cruzando pastas de projeto), e o envio de e-mail reusa o utilitário global notificacoes.js (raiz do portal), que chama a Edge Function compartilhada enviar-email (Resend). Atenção ao schema: database/database.sql, dentro da própria pasta da ferramenta, está desatualizado — é um schema MySQL antigo (camelCase, AUTO_INCREMENT, tabela configuracoes que não existe mais). O schema realmente em produção é Postgres/Supabase e vive em _sql/apresentacoes.sql (schema base + RLS + RPC) e _sql/lgpd_compliance_migration.sql (colunas LGPD adicionadas depois). Toda a documentação abaixo segue esses dois arquivos, confirmados contra o código real de admin-script.js e index.html.

Criar Apresentação

Stack e Estrutura de Arquivos

  • admin/admin.html — tela única com duas seções client-side (#criar / #historico) alternadas por data-section, sem roteamento real. Auth: bloco inline no fim do arquivo chama PortalAuthGuard.init(2) e redireciona para portal.html se !auth.isAdmin — só administradores chegam ao painel, não existe papel intermediário (equipe SCONT/Prestador) aqui.
  • admin/admin-script.js — toda a lógica: máscaras de CNPJ/telefone, busca BrasilAPI, submit do formulário, histórico, ações de desativar/reativar/excluir.
  • admin/cnae.js — parser do catálogo estático carregado por Projeto Gerenciador Formularios/cnaes.js (define window.CNAE_DATA, um CSV inline separado por ;). Filtra só linhas cujo código bate com NNNN-N/NN (subclasses) e popula window.CNAES_LISTA — dependência entre pastas de projeto, não é uma cópia local do catálogo.
  • notificacoes.js (raiz do portal, compartilhado) — Notificacoes.enviarEmail() chama a Edge Function enviar-email autenticada com o token de sessão do admin logado (auth.getSession()); Notificacoes.abrirWhatsAppCliente() só monta a URL wa.me e faz window.open — não existe envio automático de WhatsApp.
  • Busca de CNPJ é direta no navegador contra https://brasilapi.com.br/api/cnpj/v1/<cnpj> (sem proxy/Edge Function) — falha de CORS ou de disponibilidade da BrasilAPI é reportada ao usuário via toast, o formulário continua preenchível manualmente.

Decisões de Design / Particularidades

  • Payload do insert usa nomes snake_case explícitos (fd.get('razaoSocial') → razao_social etc.) — o formulário HTML usa name em camelCase, o FormData é remapeado manualmente em criarApresentacao(), não existe conversão automática.
  • cnae_principal/cnaes_secundarios são persistidos como texto já formatado ("0111-3/01 — Descrição"), não como código+descrição separados — qualquer relatório futuro que precise só do código tem que fazer parse de string.
  • formatarCodigoCnae() converte o CNAE numérico da BrasilAPI (ex.: 111301) para o formato com hífen/barra usado no catálogo local (0111-3/01) — é o ponto de acoplamento entre os dois formatos de CNAE que circulam no portal.
  • Envio de e-mail é automático ao criar (se o checkbox, marcado por padrão, estiver ligado); falha de e-mail não desfaz o insert — a apresentação já existe no banco mesmo se a Edge Function falhar, e fica disponível o botão "Reenviar Email" na tela de resultado (via _ultimaApresentacao em memória, perdido se a página recarregar).
  • Não existe tela de edição — a única forma de corrigir dados é criar uma nova apresentação e desativar a antiga manualmente no Histórico.

Dívida Técnica / Pendências

  • As colunas de auditoria LGPD (criado_por, atualizado_em, atualizado_por) existem no schema mas nenhuma tela do Boas Vindas as preenche — nem na criação, nem em desativar/reativar/excluir. A migração LGPD adicionou a estrutura mas o código nunca foi atualizado para usá-la; qualquer auditoria de "quem criou/alterou" essa apresentação não tem dado nenhum hoje.
  • database/database.sql, dentro da própria pasta do projeto, é lixo histórico (schema MySQL de uma versão anterior) e pode enganar quem procurar o schema ali primeiro — considerar removê-lo ou marcá-lo como obsoleto.

Histórico (Admin)

Stack e Estrutura de Arquivos

  • Mesmo admin-script.js — funções carregarHistorico(), atualizarEstatisticas(), filtrarHistorico(), renderizarHistorico() e as ações desativarApresentacao()/reativarApresentacao()/excluirApresentacao().
  • Estado 100% client-side em _historicoCache (array carregado uma vez por visita à aba) — busca e filtro de status rodam sobre esse array em memória, não geram nova query ao Supabase.

Decisões de Design / Particularidades

  • Os três indicadores do topo (total ativas, soma de acessos, criadas no mês) são calculados só sobre as 50 linhas carregadas — se houver mais de 50 apresentações ativas, os números exibidos não refletem o total real da tabela, só o total das 50 mais recentes.
  • Desativar é reversível (ativo volta a true); excluir é DELETE físico, sem tabela de histórico/soft-delete por trás — não há como recuperar uma apresentação excluída.
  • A confirmação de desativar/excluir usa confirm() nativo do navegador, sem modal customizado.

Dívida Técnica / Pendências

  • Sem paginação: a lista trava em 50 registros por design. Crescendo o volume de clientes, tanto a listagem quanto as estatísticas do topo ficam incompletas e isso não é sinalizado na tela (não há "mostrando 50 de N").

Página Pública do Cliente

Stack e Estrutura de Arquivos

  • index.html — página autocontida (CSS e JS inline no próprio arquivo, sem dependência de admin-script.js). Único ponto de entrada do cliente final.
  • Sem portal-auth-guard.js — a página é deliberadamente pública, não pede login. A "segurança" do link é só o UUID de id ser difícil de adivinhar, mais a RLS do banco.
  • Todo o conteúdo institucional (departamentos Fiscal/Pessoal/Contábil/Administrativo, obrigações, alertas de fraude, equipe, contatos) é HTML estático fixo na página — não vem do banco. Só o bloco "Dados Cadastrais" no topo é dinâmico.

Decisões de Design / Particularidades

  • Ausência de id na URL, id inexistente e apresentação desativada resultam no mesmo comportamento: guia genérico, sem erro visível ao cliente — não dá pra distinguir os três casos olhando só a página.
  • A chamada à RPC de contagem de acesso é assíncrona e com .catch(() => {}) — se falhar (rede, RLS, função removida), a página não trava nem avisa; o acesso simplesmente não é contado, sem log nem retry.
  • nomeCurtoEmpresa() remove sufixos societários (LTDA, ME, EPP, EIRELI, S/A, SLU) via regex só para a saudação ("Bem-vinda à Scont, Empresa") ficar mais natural — não altera o dado persistido, é só apresentação.
  • Reativar uma apresentação no Histórico é suficiente para o link voltar a personalizar — a página pública não faz nenhuma outra checagem além de ativo = true no momento do carregamento.

Dívida Técnica / Pendências

  • Risco real de exposição de dados: a policy de RLS "apresentacoes: leitura pública ativa" autoriza SELECT em qualquer linha com ativo = true, sem restringir por id. O filtro por id em index.html é só uma escolha da query do cliente, não uma regra do banco — uma chamada REST direta contra a API do Supabase com a chave anon pública (a mesma exposta em supabase-config.js), por exemplo GET /rest/v1/apresentacoes?ativo=eq.true&select=*, retorna razão social, CNPJ, telefone, e-mail e nome do contato de todos os clientes com apresentação ativa, não só de quem tem o link. Dado que a migração LGPD (_sql/lgpd_compliance_migration.sql) já classifica essa tabela como contendo dados pessoais (Art. 5º, I), essa policy provavelmente deveria restringir a leitura a um id específico (ex.: via função SECURITY DEFINER equivalente à de acesso, em vez de SELECT aberto) — não foi corrigido até o momento desta documentação.
